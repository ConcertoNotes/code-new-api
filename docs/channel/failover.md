# 渠道故障切换（失败重试 + 熔断冷却 + 自动禁用/恢复）

同一分组、同一模型下配置多个不同优先级的渠道时，系统按以下三层机制保证高优先级渠道故障时请求不会直接报错，并在其恢复后自动切回。

## 1. 单次请求内的失败重试（RetryTimes）

- 位置：`系统设置 → 模型 → 路由可靠性 → 请求重试`
- 请求先打到最高优先级的渠道；失败且状态码命中「自动重试状态码」时，下一次尝试自动降到下一优先级（已用过的渠道不会再选）。
- `RetryTimes` 默认为 **0**，即不重试。**要启用故障切换，至少设置为「优先级层级数 - 1」**（两层优先级设 1，三层设 2）。
- 504 / 524 永远不重试；默认状态码范围不含 400 与 408（可在「自动重试状态码」中调整）。

## 2. 熔断冷却（Channel failover / circuit breaker）

- 位置：`系统设置 → 模型 → 路由可靠性 → 渠道故障切换（熔断冷却）`，默认开启。
- 某个渠道在「失败计数窗口」内连续失败达到阈值（默认 3 次）后进入 **冷却**：
  - 冷却期间选路直接跳过它，请求 **零延迟** 落到下一优先级，不再每次先撞一次故障渠道。
  - 若同一模型的所有候选渠道都在冷却，则兜底放行（仍会尝试），保证不会因为熔断而拒绝服务。
- 冷却结束进入 **半开**：只放行 1 个真实请求作为探测。
  - 探测成功 → 立即恢复，流量马上切回高优先级；
  - 探测失败 → 继续冷却，时长翻倍（30s → 60s → 120s … 直到「最长冷却时长」）。
- 计入失败的错误：连接失败/超时（`do request failed`）、`channel:` 前缀错误、以及「触发冷却的状态码」（默认 `408,429,500-599`）。400/401/403/404 等不计入（401 交给自动禁用处理）。
- 定时渠道测试通过、管理员编辑渠道或手动启停渠道，都会立即清除该渠道的冷却。
- 渠道列表的「供应状态」列会显示「冷却中 / 探测中」徽标及冷却截止时间；行操作菜单提供「解除冷却」。
- 管理接口：`GET /api/channel/breaker` 查看所有冷却状态，`POST /api/channel/{id}/breaker/reset` 手动解除。
- 状态保存在各节点内存中，多节点部署时每个节点各自学习，行为一致但不共享。

## 会话亲和（Codex / Claude CLI 粘连）与故障切换的关系

- 系统默认开启「渠道亲和」：Codex CLI（`/v1/responses` + `gpt-*`）、Claude CLI（`/v1/messages` + `claude-*`）的同一会话会粘在首次成功的渠道上（TTL 1 小时，每次成功续期），以提高 prompt cache 命中率。
- 亲和优先于优先级：这就是为什么“故障切换后会话一直留在低优先级渠道、高优先级恢复了也不切回”。
- 现在的行为：
  - 粘连渠道出现渠道级故障（连接失败、5xx、429、超时）时，本次请求仍会切换到其他渠道，不再把错误原样抛给客户端；规则里的 `skip_retry_on_failure` 只拦截 401/400/404 这类业务错误。
  - 粘连渠道被禁用或处于冷却中时，直接走正常选路，不再返回 503。
  - 「切回更高优先级渠道」（`channel_affinity_setting.prefer_higher_priority`，默认开）：会话粘在低优先级渠道时，只要更高优先级的渠道健康，就切回去；同优先级不会来回跳。

## 3. 自动禁用 / 自动恢复（长期故障）

- 自动禁用（`AutomaticDisableChannelEnabled` + 渠道 `auto_ban`）：401、连接失败或命中「失败关键词」时把渠道置为「自动禁用」，彻底移出选路。
- 自动恢复（`AutomaticEnableChannelEnabled` + 定时渠道测试）：定时测试通过后重新启用。定时测试模式选「仅检查待恢复渠道」可以避免对健康渠道的额外探测。

## 推荐配置

| 项 | 建议值 |
| --- | --- |
| RetryTimes | 优先级层级数 - 1（至少 1） |
| 熔断：连续失败次数 / 窗口 | 3 次 / 60s |
| 熔断：首次冷却 / 最长冷却 | 30s / 600s |
| 自动禁用 + 自动恢复 | 开启，定时测试间隔 5~10 分钟，模式「仅检查待恢复渠道」 |
| `RELAY_RESPONSE_HEADER_TIMEOUT`（环境变量） | 上游长时间无响应时更快失败，默认 1800s，可按需调小 |
