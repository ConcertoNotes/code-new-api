# 注册与访问黑名单功能设计

## 目标

允许根管理员在系统配置中维护邮箱黑名单和 IP 黑名单。黑名单邮箱不能登录或注册；使用黑名单邮箱发起登录/注册的客户端 IP 会被自动加入全局 IP 黑名单。黑名单 IP 后续不能访问网站、API 或静态资源。

## 范围与约束

- 邮箱按完整地址精确匹配，比较前去除首尾空格并转换为小写。
- IP 按 `net.ParseIP` 规范化后的文本精确匹配，支持 IPv4 与 IPv6，不支持网段或通配符。
- 配置存储复用现有 `Option` 表和 `/api/option/` 接口，不新增数据库表或迁移。
- 两个配置项分别为 `BlacklistEmails` 与 `BlacklistIPs`，值使用每行一个条目的文本格式。
- 保留现有注册/登录限流、Turnstile、邮箱验证及 OAuth 配置；只新增黑名单检查。

## 架构

### 配置与内存状态

在 `common` 包提供黑名单状态与规范化函数，使用读写锁保护邮箱/IP 集合。`model.InitOptionMap` 注册两个默认空配置，`model.updateOptionMap` 在加载或更新选项时解析并刷新集合。解析时忽略空行、去重；邮箱条目统一规范化；IP 条目必须是可解析地址，否则更新失败并返回参数错误。

自动加入 IP 的持久化逻辑放在 `model` 包：在进程内互斥下读取当前 IP 列表、追加规范化地址、通过 `UpdateOption` 写入数据库并刷新内存，避免并发请求互相覆盖。数据库写入失败时记录错误，但调用方仍拒绝黑名单请求。

### 全局访问拦截

新增 `middleware.BlacklistIP()`，在 `main.go` 注册的全局 Gin 中间件链中、路由注册之前执行。命中 IP 时：

- `/api/` 请求返回 HTTP 403 和统一 JSON 错误消息；
- 其他请求返回 HTTP 403 文本响应；
- 调用 `Abort`，不继续执行静态资源、前端回退或任何 API handler。

IP 获取使用现有 `c.ClientIP()`，沿用项目的 trusted proxy 配置。

### 认证流程

- `controller.Register` 在邮箱规范化后、邮箱验证和用户创建前检查邮箱黑名单。命中时先自动加入当前 IP，再返回 i18n 消息“你已被拉黑”。
- `controller.Login` 在密码校验前识别登录输入对应的邮箱（直接输入邮箱或先按用户名查询用户），检查邮箱黑名单。命中时自动加入当前 IP 并返回相同消息；不改变普通错误的返回语义。
- `controller.findOrCreateOAuthUser` 在 OAuth 用户信息拿到后检查邮箱黑名单，覆盖已有 OAuth 用户登录和新用户注册；命中时自动加入当前 IP 并返回专用错误类型，由 OAuth handler 翻译为相同消息。

## 前端配置

在“系统设置 → 身份认证 → 基础认证”增加两个多行文本框：

- 邮箱黑名单：每行一个完整邮箱地址；保存时去空行、去重并以换行文本提交。
- IP 黑名单：每行一个 IPv4/IPv6 地址；说明自动封禁的 IP 也会显示在这里，支持手工删除。

扩展 `AuthSettings` 和默认值，使设置页面能通过现有 `useSystemOptions` / `useUpdateOption` 读写 `BlacklistEmails`、`BlacklistIPs`。前端不新增专用 API。

## 错误处理与安全

- 黑名单命中统一使用新的 i18n key `user.blacklisted`，中文文案为“你已被拉黑”，英文提供等价文案。
- 黑名单列表更新前在后端再次规范化和校验，不能依赖前端校验。
- 自动 IP 写入采用互斥和去重；失败只记录服务端错误，不允许请求继续通过。
- 不记录或回显密码、验证码等敏感数据。

## 测试策略

- `common`：邮箱/IP 规范化、列表解析、集合匹配和无效 IP 拒绝。
- `model`：自动追加 IP 的去重与选项持久化行为。
- `middleware`：命中黑名单 IP 返回 403 并中止后续 handler，未命中正常放行。
- `controller`：密码注册、密码登录、OAuth 登录/注册命中邮箱黑名单时返回专用消息并触发 IP 加入；正常邮箱行为不变。
- `web`：基础认证表单对两个列表进行换行解析、去重提交和默认值重置。
- 验证命令：相关 Go 包 `go test ./...`（按改动范围可先跑定向测试）；前端在 `web/` 运行 `bun run typecheck` 与 `bun run build`。
